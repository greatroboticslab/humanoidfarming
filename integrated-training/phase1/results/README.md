# Results

This directory stores all intermediate and final artifacts generated by the
video-to-robot-guidance pipeline. Each stage of the pipeline writes structured
outputs here to ensure reproducibility, debugging, and dataset creation.

The directory is organized to reflect the sequential processing stages from
transcript extraction to final robot-centric guidance generation.

---

# Purpose

The `results/` directory serves as:

- A persistent record of all pipeline outputs
- A debugging and verification checkpoint between stages
- A dataset source for instruction tuning and evaluation
- A reproducible artifact store for experiments

All downstream stages depend on files generated in earlier stages.

---

# Directory Structure

Typical structure:

results/

- timestamps_using_yt_subtitles/
- timestamps_using_whisper/
- speech_vs_nospeech_videos/
- tasks_with_timestamps/
- align_tasks_with_timestamp_transcript/ (legacy)
- frame_extractions/
- frame_captions/
- final_guidance_txt/

Each subdirectory corresponds to one pipeline stage.

---

# Stage-wise Output Description

## 1. Transcript Outputs

### timestamps_using_yt_subtitles/

Contains transcripts extracted from YouTube auto-captions.

Includes:

- Segment text
- Segment IDs
- Start and end timestamps

Used as input for task extraction.

---

### timestamps_using_whisper/

Contains Whisper-generated transcripts for local MP4 videos.

Includes:

- Whisper segments
- Precise timestamps
- Cleaned transcript text

Primary input for the recommended pipeline.

---

## 2. Speech Filtering

### speech_vs_nospeech_videos/

Contains classification results separating:

- Instructional videos (speech present)
- Non-instructional videos (little or no speech)

Purpose:

- Prevent noisy videos from entering the task extraction stage
- Improve downstream task quality

---

## 3. Task & Timestamp Grounding

### tasks_with_timestamps/

Core structured outputs from LLM-based task extraction.

Each video produces a JSON containing:

- TASK hierarchy
- SUBTASK descriptions
- Whisper SEGMENT_IDS
- Exact timestamp intervals

These timestamps are used for frame extraction and visual grounding.

---

### align_tasks_with_timestamp_transcript/ (Legacy)

Outputs from the earlier heuristic alignment approach.

Kept only for:

- Comparison
- Ablation experiments
- Historical reference

Not used in the final recommended pipeline.

---

## 4. Frame-Level Visual Grounding

### frame_extractions/

Contains frames sampled from each subtask time range.

Structure:

results/frame_extractions/<video_id>/

Files:

- taskXX_subYY_fZZ.jpg

Frames are:

- Uniformly sampled
- Limited to 3–20 per subtask
- Used for captioning and scene grounding

---

### frame_captions/

Contains JSON files with visual grounding information.

Each subtask includes:

- Frame indices
- Relative paths
- One-sentence captions generated by a vision-language model

Purpose:

- Provide visual context for robot instruction generation
- Reduce hallucinations

---

## 5. Final Guidance Outputs

### final_guidance_txt/

Human-readable robot-centric guidance.

Contains:

- One TXT file per video
- Structured subtask instructions
- References back to source JSON

Used for:

- Manual inspection
- Dataset creation
- Instruction tuning

---

# Data Format Conventions

- Each video is processed independently
- Filenames typically include the video ID
- JSON is used for structured machine-readable outputs
- TXT is used for human-readable inspection

---

# Reproducibility Notes

- Intermediate artifacts are intentionally preserved
- Enables stage-wise debugging
- Allows re-running only specific stages if needed
- Supports ablation and evaluation studies

---

# Storage Considerations

This directory may become large due to:

- Extracted frames
- Captioned frame metadata
- Multiple intermediate JSON files

Recommended:

- Periodic cleanup of unused legacy outputs
- Optional compression of frame directories
- Versioning important experiment runs
